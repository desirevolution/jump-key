# Review and refactoring

## Agreed scope

Docker and standalone executable; existing UI and shortcuts retained. Demo branch unchanged. One user per installation, offline configuration retained. Existing configuration, favorites and Continue history migrated. No multi-device conflict handling.

## Changes

- Shared configuration migration, reference migration and persistence module.
- Deterministic IDs for legacy services; persisted IDs survive renaming/reordering.
- Browser references use IDs; duplicate legacy names map to the original first match.
- Editor waits for HTTP success; failed writes retain edits and leave cache unchanged.
- Go server saves previous bytes before replacing configuration, including the first migration.
- Structural validation of services, IDs, keys and engines; malformed inputs rejected.
- Automatic keyboard keys reserve all explicitly assigned keys first.
- Raw configuration retained for editing/export, preserving additional fields and omitted auto-keys.
- One offline configuration cache in localStorage; removed stale duplicate service-worker cache.
- Storage write errors no longer turn successful HTTP saves into apparent failures.
- Editor teardown and pending-load disconnect cleanup.
- Removed unused keyboard-handler.js, Caddyfile and Dockerfile_old; current Docker build includes all Go files.
- README now describes Go, migration, backups and verification.

## Remaining limitations

- Last writer wins; no version/ETag conflict handling, as agreed.
- Offline storage is not isolated between accounts.
- Direct file changes must preserve IDs if renamed services should retain favorites.
- Browser-only settings and favorites remain local to each device.
- Backups have no retention policy.
- Frontend development server does not implement PUT; use Go for persistence checks.
- Dependency updates from 2026-10-03 are recorded below. The build still emits a vite-plugin-pwa/Rolldown deprecation warning.

## Verification results

- `npm ci` and `npm run build`: successful.
- `npm test`: 6 regression tests passed (bundled configs, ID migration, references/renames, malformed data, key collisions, HTTP failure propagation).
- `go test -race ./...`: passed (backup contents, rejected writes, backup failure).
- `go vet ./...`: passed.
- Standalone Linux executable: built and exercised over HTTP; migration, original backup, readback and invalid-write rejection passed. The sandbox required `-buildvcs=false` because its parent workspace has unavailable VCS metadata.
- Browser/UI execution: not completed. Chromium is absent and its download did not yield a valid archive. Manual check still needed: failed-save dialog retention, editor teardown/reopening, keyboard favorites and offline reload.
- Docker image was not built here; it uses the verified frontend/Go build and now copies all Go source files.

- Successful saves clean removed favorite/history references and leave a removed active category. IDs and references survive moves.
- Updated all four languages, help and README. 19 tests and production build passed; Android/browser visual checks remain outstanding.
